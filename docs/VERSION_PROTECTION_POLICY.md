# 📋 版本變動防護政策

## 🎯 核心原則

**所有會改變本地檔案版本的 Git 操作,必須事先取得 Rosy 的明確同意確認**

---

## 🚨 絕對禁止的危險操作

### ❌ 1. 強制重置 (Force Reset)
```bash
# 絕對禁止!會直接丟棄本地變更
git reset --hard <任何目標>
git reset --hard origin/develop
git reset --hard HEAD~1
```

### ❌ 2. 強制推送 (Force Push)
```bash
# 絕對禁止!會覆蓋遠端歷史
git push --force
git push -f
git push --force-with-lease
```

### ❌ 3. 檢出並丟棄變更 (Checkout with Force)
```bash
# 絕對禁止!會丟棄未提交的變更
git checkout -f
git checkout -- .
```

---

## ⚠️ 需要明確確認的操作

### 🔄 1. 拉取遠端變更 (Pull)
```bash
# 需要確認!可能會合併或覆蓋本地變更
git pull origin develop
```

**執行前必須詢問:**
- "遠端有新的變更,是否要拉取並合併到本地?"
- 顯示即將合併的 commits 清單
- 說明可能的衝突風險

### 🔀 2. 合併分支 (Merge)
```bash
# 需要確認!會引入其他分支的變更
git merge <分支名稱>
```

**執行前必須詢問:**
- "是否要合併 `<分支名稱>` 到當前分支?"
- 顯示兩個分支的差異摘要
- 說明可能的衝突

### 🎯 3. 變基操作 (Rebase)
```bash
# 需要確認!會重寫提交歷史
git rebase <分支名稱>
```

**執行前必須詢問:**
- "是否要將當前分支變基到 `<分支名稱>`?"
- 說明歷史會被重寫
- 警告可能的風險

### 🔄 4. 檢出其他分支或提交 (Checkout)
```bash
# 需要確認!會切換工作目錄內容
git checkout <分支名稱>
git checkout <commit-hash>
```

**執行前必須詢問:**
- "是否要切換到 `<分支名稱>`?"
- 確認當前分支沒有未提交的變更
- 提醒切換後檔案內容會改變

### 📂 5. 從其他版本恢復檔案 (Restore from History)
```bash
# 需要確認!會用舊版本覆蓋當前檔案
git checkout <commit> -- <檔案路徑>
git restore --source=<commit> <檔案路徑>
```

**執行前必須詢問:**
- "是否要用 `<commit>` 的版本覆蓋當前的 `<檔案>`?"
- 顯示當前版本和目標版本的差異
- 警告會丟失當前未提交的變更

## ✅ 安全操作 (可自動執行)

### 📊 查詢類操作 (只讀,不修改)
```bash
git status              # 查看狀態
git log                 # 查看歷史
git diff                # 查看差異
git show <commit>       # 顯示提交內容
git branch -a           # 列出所有分支
git reflog              # 查看操作記錄
```

### 💾 本地提交操作 (不影響遠端)
```bash
git add <檔案>         # 暫存檔案
git commit -m "..."    # 本地提交 (已在 GIT_WORKFLOW.md 中要求確認)
```

### 📤 推送到遠端 (已在 GIT_WORKFLOW.md 中要求確認)
```bash
git push origin <分支>  # 推送本地提交到遠端
```

## 🛡️ 防護檢查清單

在執行任何 Git 操作前,AI 助手必須檢查:

1. **操作類型檢查**
   - [ ] 這個操作是否在「絕對禁止」清單中? → 拒絕執行
   - [ ] 這個操作是否在「需要確認」清單中? → 詢問 Rosy
   - [ ] 這個操作是否在「安全操作」清單中? → 可以執行

2. **版本變動影響檢查**
   - [ ] 這個操作會改變工作目錄的檔案內容嗎?
   - [ ] 這個操作會丟棄未提交的變更嗎?
   - [ ] 這個操作會修改提交歷史嗎?

3. **確認訊息格式**
   ```
   ⚠️ 版本變動確認請求
   
   操作: <git 指令>
   影響: <說明會造成什麼變化>
   風險: <說明可能的風險>
   
   即將變動的檔案:
   - <檔案1>: <變動說明>
   - <檔案2>: <變動說明>
   
   是否要執行這個操作?
   ```

## 📌 AI 助手行為準則

作為 AI 助手,在處理 Git 操作時:

1. **預設立場:保守謹慎**
   - 有疑慮就問,不要自作主張
   - 寧可多問一次,也不要擅自執行危險操作

2. **版本變動必須透明**
   - 明確告知操作會造成什麼變化
   - 顯示變動前後的差異
   - 說明可能的風險和影響範圍

3. **尊重使用者的本地變更**
   - 本地檔案是使用者的心血結晶
   - 任何會覆蓋本地檔案的操作都需要確認
   - 提供退路和恢復方案

4. **記錄重要操作**
   - 在本文檔記錄重大版本變動事件
   - 分析原因並提出改進措施
   - 持續優化防護機制
